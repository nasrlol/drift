MAP DATA

Source: OpenStreetMap extract of Belgium from Geofabrik (ODbL, credit "(c) OpenStreetMap contributors")
  https://download.geofabrik.de/europe/belgium/belgium-261119.osm.pbf
  saved as assets/raw/belgium.osm.pbf (668 MB, not in git)
  note: the "belgium-latest" link was broken (404), so we use a dated file

Tool: GDAL (ogr2ogr), installed with micromamba, no sudo:
  micromamba create -n gis -c conda-forge gdal

tools/extract_map.sh
  pulls 4 layers out of the .pbf into assets/geojson/ (1.7 MB total)
    border.geojson     Belgium outline (1 polygon)
    rivers.geojson     waterway=river
    motorways.geojson  highway=motorway
    cities.geojson     place=city (15 points)
  keeps only the name field, simplifies lines, 5 decimal coordinates
  takes a few minutes (most of it on the border)

tools/bake_map/  (odin run tools/bake_map, from repo root)
  reads the geojson files, writes assets/belgium.bin (422 KB)
  projection: equirectangular, km, origin top-left (lon 2.38, lat 51.56), y down
  10872 lines, 36364 points, 15 cities, 15 hubs

belgium.bin format (version 2, all little endian, 4-byte aligned)
  header  magic "DRFT", version, line_count, point_count, city_count, hub_count (6 x u32)
  lines   start, count, kind (3 x u32)   kind: 0 border, 1 river, 2 motorway
  points  x, y (2 x f32, km)
  cities  pos (2 x f32), name (32 bytes, 0-terminated)
  hubs    pos (2 x f32), name (32 bytes, 0-terminated). For now one hub per city, same position.
          max MAX_HUBS = 32 (bake fails above that). Tower top = ground + HUB_TOWER_M (58 m, spec).

WEATHER DATA

Source: Open-Meteo forecast API v1 (CC BY 4.0, free for non-commercial use, no key)
  https://api.open-meteo.com/v1/forecast
  one request for all 63 grid points: latitude=..&longitude=.. (comma lists),
  hourly=wind_speed_{975,950,925}hPa,wind_direction_{975,950,925}hPa,wind_speed_10m,wind_gusts_10m,cloud_cover,
  forecast_hours=9&wind_speed_unit=ms&timezone=GMT&timeformat=unixtime
  hour 0 = the current UTC hour. Open-Meteo counts every location as one call (10000 / day free),
  so 63 points refreshed every 15 min = ~6000 / day. A finer grid needs a slower refresh.
Grid: 9 x 7 points every 40 km from the map origin (lon 2.38, lat 51.56), covers the 285 x 229 km map.
  lat = 51.56 - y / 111.32, lon = 2.38 + x / (111.32 cos 50.5), same projection as the bake tool.
Gust index: Open-Meteo has gusts only at 10 m. index = clamp((gust_10m - wind_10m) / 10 m/s, 0, 1)
  x (1.08 - LAYER_ALT / 1600), the height factor from the spec. Cloud = cloud_cover % / 100 (total cover).
Validation (reject the whole response, keep the old snapshot): 63 locations, 9 values per series, no null,
  wind speeds and gusts 0..100 m/s, directions 0..360, cloud 0..100 %, times 2020..2100 on whole hours,
  hour h = start + h x 3600 in every cell. The range test also rejects NaN and +-Inf.
  Checked by feeding edited responses (null, out of range, shifted time, short series, 62 locations, Inf, html).
Measured (2026-11-21, macOS arm64): one fetch ~400 ms, ~1.2 MB scratch (json values).

ELEVATION DATA

Source: Copernicus DEM GLO-90 (3 arc seconds, ~90 m), public release on AWS Open Data, tiles Last-Modified 2022-05-09
  https://copernicus-dem-90m.s3.amazonaws.com/Copernicus_DSM_COG_30_N<lat>_00_E<lon>_00_DEM/<same name>.tif
  license: free and open (Copernicus DEM licence), attribution required:
  "(c) DLR e.V. 2010-2014 and (c) Airbus Defence and Space GmbH 2014-2018 provided under COPERNICUS
  by the European Union and ESA; all rights reserved"
tools/download_dem.sh (from anywhere): 15 tiles N49..N51 x E002..E006 (named after their south-west corner,
  map spans lat 49.43..51.56, lon 2.38..6.42) into assets/raw/dem/ (60 MB, not in git), skips tiles it has,
  treats 404 as a sea tile, then checks every file against tools/dem_tiles.sha256 (pins the exact data,
  the bucket has no versioned paths). All 15 exist, none is sea only. ~7 s on a fast line.
Tiles: float32 GeoTIFF (COG), heights in m above EGM2008, AREA_OR_POINT=Point. 1200 x 1200 below 50 N,
  800 x 1200 from 50 N (longitude spacing doubles to 4.5 arc seconds). A surface model: buildings and
  forest are in the heights. Checked: coast tile N51 E002 -5.7..41 m, Ardennes N50 E005 max 668 m.

CODE LAYOUT
source/game/      package game, all game code, builds as build/game.so (debug) or into the exe (release)
  game.odin       World struct, exported procs, fixed 60 Hz timestep, drawing
                  Sim speed: keys 1..4 set w.sim_speed = 1x / 5x / 15x / 40x (SIM_SPEEDS). The frame time (capped at
                  0.25 s) is multiplied before it goes into the accumulator, so 40x runs up to 40 steps per 60 fps frame
                  (600 at most after a hitch) and every step still has dt = 1 / 60.
                  w.font: Roboto rasterized by raylib on the first frame (needs a window, so never in headless),
                  FONT_PX 14, codepoints 32..255. Falls back to the raylib font with a log line if loading fails.
                  Unloaded in game_shutdown. The profiler overlay still uses the raylib font.
                  "(c) OpenStreetMap contributors" (with a real copyright sign) bottom right on a white box,
                  required by the ODbL wherever the map is shown.
                  Camera: w.view (View) = pan (km from the map centre to the screen centre) + zoom (log2 relative
                  to the fitted view, ZOOM_MIN -1 .. ZOOM_MAX 7). Zero = the whole map fitted to 95% of the window.
                  Each frame it becomes a Camera2D, zoom = px per km. Pan is clamped so the screen centre stays on
                  the map. Two modes, key M toggles, w.drive_mode (zero = map mode):
                  Map mode: the camera reads w.controls, throttle / turn pan (600 px/s), climb zooms (2 per s) around
                  the screen centre. So WASD and the left stick pan, R/F and right stick Y zoom. Mouse (camera only,
                  not in Controls): left drag pans, wheel zooms (0.25 per notch) around the cursor. The ship does not
                  step and nothing is recorded.
                  Drive mode: Controls go to ship_step and the replay record, the camera sits on the ship, only the
                  wheel zooms. The ship is drawn as an 8 px red triangle pointing along its heading in both modes.
                  Start: game_init puts the ship on the Brussels tower (hub named "Bruxelles - Brussel", looked up
                  by name since hub ids follow the bake order), alt = height_at + HUB_TOWER_M, heading north.
                  Only on a fresh World, a hot reload keeps the ship where it is. Missing hub: log line, map corner.
                  Colors (render.odin): every drawn color comes from Palette = the design token table
                  (docs/drift-design.pdf "Kleuren": surface, surface_2, surface_3, text, text_2, line, accent,
                  accent_strong, green, banner, banner_2, red, warning, reroute, arrived, sheet, chip, bubble,
                  bubble_text, pill), one per Theme in PALETTES. Night is zero (the design default), key T and the
                  toolbar switch. palette(w) -> ^Palette returns w.palette, a copy of PALETTES[w.theme] made at the
                  start of every frame: no pointer into this library's constants, so hot reload is safe. Map line
                  colors go to the line shader as a uniform, switching rebuilds nothing. The profiler overlay keeps
                  its own fixed colors.
                  Map colors (same Palette, design "Kaart" table): land, city, park, farmland, marsh, beach, water,
                  roof, wall, motorway / main_road / street / track with their _casing, route / alt_route with their
                  _casing, sky, horizon. Used now: land (clear color), water (rivers), motorway; the border has no
                  design color and uses text_2. Wind trails use text: the design names a speed ramp (white < 6 m/s,
                  mint < 10, yellow < 14, coral above) without values, open question.
                  Line meshes (Line_Meshes in render.odin, built inline in game_update): map lines and wind trails
                  are meshes drawn by one shader (LINE_VS, GLSL 330), built on the first frame (needs the window,
                  never in headless). Each segment is 6 vertices (2 triangles, no index buffer: raylib indices are
                  u16). Every vertex carries both ends (vertexPosition = A, vertexNormal.xy = B); the shader picks
                  the corner from gl_VertexID % 6 and pushes it along the screen space normal, so lines are 1 px at
                  every zoom. vertexColor.r = index into a uniform color array (Map_Kind colors, then WIND_COLOR),
                  vertexColor.a scales the alpha. The CPU arrays live in the frame arena; after UploadMesh the mesh
                  pointers are set to nil, so UnloadMesh only frees GPU buffers. Rebuilt after a hot reload (the
                  shader may have changed), unloaded in game_shutdown.
                  Map: static, 25493 segments, 152958 vertices, 4.1 MB on the GPU, one DrawMesh.
                  Wind: dynamic mesh, rewritten every frame with 3 UpdateMeshBuffer calls, one DrawMesh.
                  Measured 2026-11-21 (Asahi M2, 800 x 450, debug): map draw 8.6 ms with DrawLineStrip -> 0.55 ms
                  with the mesh. The first frame takes ~34 ms (mesh build).
                  Wind particles (Wind_Particles in render.odin, w.wind): WIND_PARTICLES 600, SoA arrays x, y, vx, vy,
                  age in World. Drawing only, never read by the simulation, so frame time is used. Spread over the
                  visible part of the map, respawned there when they leave the view or reach WIND_LIFE_S 3 s; the
                  first frame (seeded = false) gives them random ages. Seeded LCG (wind_rand), same picture every
                  run. Velocity = wind_at of layer 0 (until the layer toggles) at the forecast hour of w.tick,
                  shown at WIND_PX_PER_MS 4 px/s per m/s at every zoom. Trail = 0.4 s of travel, fades in and out
                  (sin of age), not drawn under WIND_CALM_MS 0.5. No snapshot = calm = no particles.
                  Measured (same machine, draw ms, map + wind + labels): debug 1.8, -o:speed 0.7. With 1500
                  particles: DrawLineV per particle cost 0.5 ms (-o:speed); the mesh writes cost ~3.4 ms in debug,
                  so the count went down to 600, which still shows the wind clearly.
                  Labels (Label in render.odin): after EndMode2D, each city goes through GetWorldToScreen2D into a
                  flat [dynamic]Label in the frame arena: dot, text rect (LABEL_GAP_PX 2 px bigger on every side),
                  text. Cities with dot and text off screen are dropped. A label whose rect overlaps an earlier shown
                  one keeps only its dot. Earlier = first in the bake: there is no population to rank by yet. Then one
                  pass draws dots (3 px) and texts (default font, LABEL_PX 10). Pixel size stays the same at every
                  zoom. The default font covers Latin-1, "Liege" with e grave draws correctly. 15 cities: O(n^2)
                  overlap test, fine until there are hundreds of labels.
  ui.odin         Fonts: Font enum (Figtree 500/600/700/800 + italic 400, Roboto 400/500/700, Mono 400/600),
                  font_get rasterizes each (font, px) pair on first use (codepoints 32..255, up to 64 pairs in
                  w.fonts), fonts_unload in game_shutdown. ui_text(w, pos, text, font, px, color) draws at the
                  top-left pos, ui_text_size measures. The OSM credit and the toolbar use them.
                  Immediate mode UI, our own (raygui needs a system library on Linux, it is not in the build).
                  A widget is a proc call that draws itself and returns what happened this frame; nothing is kept
                  between frames. ui_button(rect, text, on, pal) -> clicked: on = button_on color, mouse over =
                  button_hot, default font 10 px. Toolbar top right (TOOLBAR_W x TOOLBAR_H, laid out in
                  game_update before the camera so the mouse does not pan or zoom the map under it, drawn after the
                  labels): Map / Drive, sim speeds (names from SIM_SPEEDS), Day / Night. Keys M, 1-4, T still work.
                  A click changes the state after the frame's update, so it shows from the next frame.
  map.odin        same structs as the bake tool (keep in sync). #load embeds belgium.bin,
                  load_map() slices it, no parsing. Re-pointed in game_hot_reloaded.
                  Hubs are copied into a fixed array w.m.hubs[:w.m.hub_count], hub id = index.
  terrain.odin    height_at(w, x, y) -> ground height in m. Stub: 0
  weather.odin    wind_at(w, x, y, layer, hour) -> [2]f32 m/s, direction the wind blows toward, x east, y south
                  gust_at(w, x, y, layer, hour) -> 0..1, cloud_at(w, x, y, hour) -> 0..1. Bilinear on the 40 km grid
                  from w.weather, no allocation. Outside the grid the edge value holds, layer and hour are
                  clamped (hours after 8 keep hour 8). Until a snapshot is loaded w.weather is zero: calm, clear.
                  3 layers = 975 / 950 / 925 hPa ~ LAYER_ALT 300 / 550 / 800 m, hours 0..8 from snapshot start
                  Weather struct: start (unix s), wind [hour][layer][cell][2]f32, gust [hour][layer][cell] 0..1,
                  cloud [hour][cell] 0..1. Fixed size 22.7 KB, zero = calm and clear.
  net.odin        fetch_weather(out, scratch, cancel) -> ok: blocking Open-Meteo request with curl (15 s timeout,
                  max 1 MB, aborts within ~1 s when cancel is set), converts the json into a Weather.
                  Writes out only if every value is valid.
                  Snapshot cycle (state in w.fetch, zero = fetch on the first update):
                    game_init -> weather_load_snapshot(w, path): reads cache/weather.snap, checks size, magic, version,
                      sha256 and weather_valid. Bad or missing file: weather stays zero, fetch right away.
                    game_update -> weather_poll: every frame, starts a thread when now >= next (15 min after
                      the snapshot was fetched, 5 min after a failure). The thread fetches, hashes and writes
                      the file (temp + rename), all allocation in w.fetch.mem. When is_done, the frame loop
                      copies the 22.7 KB Weather into w.weather. No network or disk IO in the frame loop.
                    game_before_reload / game_shutdown -> weather_stop: cancel + join (measured 5-14 ms),
                      because the thread runs code from the library that is about to be unloaded.
                  cache/weather.snap: Snapshot_Header (magic "DRWS", version 1, fetched_at unix s,
                  sha256 of the Weather bytes) + raw Weather, 22736 bytes. w.weather_hash = that sha256.
                  Identity: game_init -> identity_load_or_create. cache/identity.key holds the 32 byte ed25519
                    seed (owner-only permissions). Missing: generate from the system entropy source and save.
                    Present but wrong size or invalid: logged and left alone (it is the user's reputation),
                    w.identity stays zero and network features stay off. w.identity_pub = public key,
                    logged as the first 8 bytes in hex. Moves to the user data folder with the release item.
                  Carpool messages: Message is 208 bytes, fixed size, little endian, no implicit padding
                    (#assert). Header: magic "DRMS", version 2, kind (Offer / Request / Accept / Review),
                    time (unix s, set by the author), author (ed25519 public key). Body is a raw union:
                      Offer   from_hub, to_hub, seats 1..8, mode, depart, arrive, weather snapshot hash, energy_kwh
                      Request offer id, from_hub, to_hub, seats 1..8, passenger x25519 public key (not zero)
                      Accept  offer id, request id, driver x25519 public key (not zero)
                      Review  subject public key, accept id, stars 1..5
                    sig = ed25519 over bytes 0..143. Message id = sha256 of all 208 bytes. Version 2 since the
                    trip key exchange; node hello version 2 too, so old nodes are refused.
                    msg_sign(w, m) fills magic, version, author, sig (start from a zeroed Message).
                    msg_read(bytes) -> (m, why) for anything from outside: msg_check (size, header, field
                    ranges) then the signature. why is "" or a constant reason, the caller logs it (network
                    threads have no World). msg_check alone is for the store file.
                    Measured (macOS arm64, -o:speed): sign ~33 us, read + verify ~44 us.
                  Message store: w.store (Store, ~0.9 MB in World) holds up to STORE_MAX = 4096 messages and
                    their ids, unordered, removal moves the last one into the hole. Bounded so one key cannot
                    fill a node: STORE_PER_AUTHOR = 64, an author over it loses its oldest message (by time).
                    Expiry: an offer at its depart time, the rest 30 days after their time. Times more than
                    1 h ahead are refused (they would never expire). Full store: drop expired, then the one
                    that expires first, or refuse m (.Full) when m itself expires first.
                    store_add(s, m, now) -> Added / Duplicate / Expired / Future / Full, memory only, m must
                    have passed msg_read. Every access takes s.lock (sync.Mutex, zero is unlocked): the
                    network thread writes, the frame loop reads.
                    cache/messages.log: messages back to back, append-only while running (store_append).
                    store_load(s, path, now, scratch) at start: header + field check per message (no
                    signatures: only verified messages are ever written), then store_rewrite writes it again without
                    expired / dropped ones (temp file + rename). Also rewritten when it reaches 2 x STORE_MAX
                    messages. A size that is not a multiple of 208 (killed mid-append, or a v1 file) moves to
                    messages.log.bad and the store starts empty; peers send the messages again.
                    Load of a full file ~12 ms (linear dedupe, 4k x 4k id compares), so it runs on the
                    network thread, not in game_init.
                  Peer to peer node: every game is one, there is no server. w.node (Net_Node) holds the peers,
                    the threads and per-thread buffers (2 x 128 KB id lists). node_poll(w) each frame starts it
                    after start and after every reload, node_stop(w) in game_before_reload / game_shutdown.
                    Two threads, blocking with timeouts (5 s per send / recv):
                      serve: listens on NODE_PORT 7419 (w.node.port overrides it, 0 = default), non-blocking
                        accept every 50 ms so it can stop, one connection at a time, max 30 s each.
                      sync: loads the store first (store_load), then every SYNC_S = 30 s per peer: asks the
                        peer's ids since T, gets the missing ones (64 per request, each through msg_read and
                        checked to be one it asked for), pushes ours it does not list.
                        T = 0 (all) once an hour per peer, otherwise the last good sync - 10 min.
                        A failed sync backs off: 30 s x 2^fails, max 32 min.
                    Protocol, one TCP connection, the dialer asks until it closes:
                      both: hello = magic "DRNP" u32le, version u8, listen port u16le (0 = not listening),
                        node id [8]u8 (random per run)
                      'I' since i64le -> count u32le + ids;  'G' count + ids -> count + messages;
                      'P' count + messages -> added u32le;  'N' -> count u8 + peers (family u8, address
                      [16]u8, port u16le). Counts above STORE_MAX / SYNC_BATCH / MAX_PEERS close it.
                    net_dial (dial_posix.odin / dial_windows.odin): net.dial_tcp has no connect timeout (a
                    dead address blocks ~75 s), so non-blocking connect + poll, 5 s max, checks the stop flag
                    every 100 ms. Stop while dialing a dead peer: ~10 ms.
                    Store writes from both threads: s.file_lock around appends and rewrites.
                    Peer list (max 32): seeds from SEED_NODES (in code, empty until there is a public node)
                    and cache/seeds.txt (one "host:port" or "host" per line, # comments, resolved on the
                    sync thread). Learned: every 'N' answer (peers that synced in the last 24 h) and every
                    node that dials us (its address + the listen port from its hello). Learned peers are
                    saved to cache/peers.txt (text) and read back at start. A learned peer that fails 8
                    syncs in a row (~5 h with the back off) is forgotten, seeds stay. A full list drops the
                    learned peer that failed most, never one that works. A hello with our own node id
                    means we dialed ourselves (our address came back through others): dropped, and that
                    address is never added again this run.
                    Measured (localhost): two nodes with 120 + 80 messages both end with 200 in one sync.
                    Three nodes where B and C only know A: after one round each knows the other two.
                  Weather between peers: Snapshot = Snapshot_Header + Weather, the exact file / wire bytes.
                    snapshot_check(bytes) -> (^Snapshot, why): size, magic, version, sha256, weather_valid.
                    The one check for disk (weather_load_snapshot, cache/snaps) and network.
                    cache/snaps/<sha256 hex>.snap, max SNAP_KEEP = 32 (~730 KB): the node's own snapshot
                    (fetch thread after every fetch, cache/weather.snap at start) and every snapshot a live
                    offer in the store names (offer.weather). After each sync the node asks that peer
                    ('W' + sha256) for up to 4 it does not have; a peer that lacks one answers 0 and it
                    does not count. Kept only when snapshot_check passes and the hash is the one asked
                    for. Full: drop the oldest (fetched_at) that no live offer names, else the oldest.
                    Names are written from the hash digit by digit, never from peer text. Files that fail
                    the check at start are deleted. snap_read(sha256, out) for the game: a passenger
                    recomputes an offer's route with the driver's weather (matching / verify items).
                    Weather still only reaches the simulation through a file and snapshot_check.
                  Trip and live position (w.trip, one trip at a time, zero = none, frame loop only):
                    trip_keypair(w) -> x25519 public key, fresh per trip, goes into the signed Request
                      (passenger) or Accept (driver), so the key exchange is authenticated by ed25519.
                    trip_start(w, request, accept, driver): checks accept answers that request and offer and
                      that this user is the author of its side, x25519 shared secret (all zero = low order
                      point, refused), key = HKDF-SHA256(salt accept id, ikm shared, info "drift live position
                      v1"), wipes the private half. Trip id = accept id. trip_end(w) wipes it.
                    Live_Packet (88 bytes): trip id, seq, from_driver, Live_Position (x, y km, alt m, time)
                      encrypted with ChaCha20-Poly1305, header bytes as aad. Nonce = seq + direction byte, so
                      both directions share the key but never a nonce. live_seal / live_open; open drops the
                      own direction, seq <= last accepted (replay) and anything that does not verify.
                    Game side: live_send(w, pos) seals and leaves the packet in w.node.live_out, live_poll(w)
                      opens the newest one the node thread found. No network in the frame loop.
                    Through peers (node_live, sync thread, every 1 s while live_out is set): the packet goes
                      to this node's own table and to up to 8 peers that synced in the last minute ('L'),
                      and each is asked for the other direction's latest ('M'); the highest seq wins. Not
                      gossiped: it reaches the other side through any node both talk to. Nodes keep the
                      latest packet per trip and direction, 1024 slots, 60 s, memory only, never on disk,
                      and cannot read them. A node cannot tell garbage with a higher seq from a real packet,
                      so someone who knows a trip id can spoil it at one node; the receiver asks every node
                      it reaches and only keeps what verifies.
                    Tested: two processes, offer -> request -> accept through sync, both started the same
                      trip, positions both ways every second (heard 19 of 24, only the newest is kept).
                      The 21 checks from #25 (replay, flipped ciphertext, changed seq, own direction, guessed
                      key, low order point, a third user claiming the passenger role) pass on the node table.
                  Headless node: drift --headless --node [--port <n>] (debug host and release exe). game_init,
                    then node_poll, no window and no frame loop, runs until killed. Same store, sync, peer
                    files and cache/ as the game, so run it in its own directory. Exits 1 when it cannot
                    listen (a node nobody can reach helps nobody). "[node] 120 messages, 3 peers,
                    2 reachable" every 5 min. Killed mid-append the store file can end in a partial
                    message: the next start moves it to messages.log.bad and starts empty, peers resend.
                  The same format is used by headless --snapshot, test/data and bench. Logs go to stderr.
  debug.odin      tools for finding bugs. Profiler: prof_begin() / prof_end(w, block, tick) store the last ms of
                  Update, Draw, Route, Weather_Load in w.prof, compiled out in release (PROFILING =
                  DRIFT_DEBUG || DRIFT_PROFILE). Overlay drawn in game_update, F3 toggles: frame ms with
                  update / draw split, worst of the last 120 frames, route and weather load ms, perm / route
                  arena used / reserved, frame arena use, 120 frame graph (yellow line = 4 ms budget, red bars
                  over it). Frame ms excludes EndDrawing (vsync wait) and the overlay itself.
                  Headless: ./build/drift --headless --snapshot <file> --inputs <file> runs without a window,
                  prints the result to stdout (deterministic text, no timings) and timings / errors to stderr,
                  exit code 0 or 1. game_headless (exported, called by host and release main) reads the inputs,
                  headless_run(w, snapshot_path, inputs, out) loads the snapshot (weather_load_snapshot, the
                  cache/weather.snap format) and does the work and is what test/ calls.
                  Inputs: one command per line, # comment. "route <from hub> <to hub> <mode> <hour>",
                  hub = index into w.m.hubs, mode fastest / greenest / calmest, hour 0..8.
                  "no_fly <x km> <y km> <radius km> <ceiling m>" fills the next free slot of w.no_fly.
                  Output per route: "route 6 -> 11 fastest hour 0: 2 points, 104.812 km", then x y alt per point.
                  --dump appends the state dump after the result.
                  Log: logf(w, system, format, args) prints "[route t=1234] message" to stderr, t = w.tick.
                  No allocation (1 KB stack buffer, longer messages are cut). Code without a World
                  (fetch thread, argument parsing) prints "[system] message" with fmt.eprint.
                  State dump: dump_world(w, out) writes tick, build, map counts, hubs, weather start / sha256 /
                  fetched_at, a weather line per hour
                  (max wind per layer, max gust, mean cloud), no-fly zones, blocked nodes per layer
                  and arena used / reserved. No timings, so two dumps
                  of the same run are identical. F5 in the app prints it to stdout, --dump in headless mode.
                  Windows release is -subsystem:windows and has no console: use the debug or profile exe there.
  ship.odin       Controls struct: throttle, turn, climb, each -1..1, zero = neutral. Filled by input, read by the
                  camera in map mode (game.odin), by ship_step in drive mode.
                  Ship: pos (km, map space), alt (m), heading (rad clockwise from north), speed (m/s), turn_rate (rad/s).
                  ship_step(w, controls, dt) runs once per fixed 60 Hz step in game_update on w.ship, reads only the
                  ship, the controls and height_at. Limits: speed follows max(throttle, 0) * 35 m/s with +1.2 / -1.6
                  m/s^2, turn rate follows turn * 0.6 rad/s with a 0.5 s time constant, climb 5 m/s, altitude clamped
                  to height_at + 28 m .. 900 m. Wind: ground velocity = heading * speed + wind_at of the layer nearest
                  to the altitude, hour = tick / (60 * 3600). Battery comes later.
                  Ship.warnings: bit_set of Terrain (less than 60 m above the ground) and No_Fly (inside a w.no_fly
                  circle below its ceiling), rebuilt every step. The UI only reads it.
                  Ship.docked / dock_hub: set when within 30 m horizontally and 25 m vertically of a hub's tower top
                  (ground + HUB_TOWER_M), first hub in index order, rebuilt every step.
                  Replay: every step the controls are packed to Control_Step ([3]i8, 3 bytes) and the ship steps with the
                  unpacked value, so the recording reproduces the path exactly. w.replay.steps is 60 * 3600 steps (1 h,
                  648 KB) from the perm arena, w.replay.count says how many are filled, recording stops when full.
                  Bench (profile build, 2026-11-21, Windows, height_at still a stub): ship_step min 59 / avg 65 / max 319 ns
                  against the 1 us budget. It is ~2 sin/cos, wind_at (8 ns), 15 hub distances and 8 zone checks. The tower
                  height_at is only called for a hub that is within 30 m horizontally, not for all 15, because the real
                  height_at will cost more than the stub.
  input.odin      read_controls() -> Controls, called once per frame into w.controls. W/S throttle, A/D turn (right = +),
                  R/F climb up / down (arrows = W/A/S/D, PgUp / PgDn = R / F), gamepad 0: left stick throttle + turn, right stick Y climb. Keyboard and stick
                  add up, clamped to -1..1. Deadzone 0.15, rescaled so the stick still reaches 1.
  route.odin      route(w, from, to, mode, hour) -> (path, ok). Points are [3]f32 (x km, y km, alt m).
                  ok = false means no safe route with this wind. Hub positions: w.m.hubs.
                  from.z / to.z are the tower tops (headless: height_at + HUB_TOWER_M).
                  Path lives in w.route_mem until the next call: the smoothed path below, from the tower top
                  + 6 m at from to the tower top + 6 m at to. A* never enters a blocked node (see below).
                  ok = false also when from or to has no free node within 5 cells (outside the grid,
                  inside a no-fly zone): grid_free_node_near picks the closest free cell centre, lowest free
                  layer first (spec), the altitude of the end point is not used.
                  Grid: 286 x 237 cells of 1 km x 3 layers (LAYER_ALT) = 203,346 nodes, covers every point
                  in belgium.bin (x 0.6..285.2, y 1.0..236.5 km). node = layer * 286 * 237 + y * 286 + x,
                  each layer a contiguous row-major plane. grid_node_at(pos) snaps to the cell under x, y
                  and the closest layer, grid_node_pos(n) gives the cell centre, grid_neighbor(n, d) steps
                  one entry of GRID_DIRS (8 horizontal directions, up, down) and fails past the edge.
                  w.grid holds the search state as fixed arrays in World (no arena, allocated with World):
                  visit stamp, cost, parent, heap slot and heap item per node. A node's cost and parent only
                  count when visit[n] == grid.search, so a route starts with search += 1, not a 4.9 MB clear.
                  Cost per mode (spec), edge_cost(g, a, b, mode) for neighbour nodes:
                    fastest  18 m/s  seconds          dt                                vertical 0.2 x climb m / 3
                    calmest  13 m/s  seconds          dt x (1 + 7 g^2)                  vertical 0.2 x climb m / 3
                    greenest 11 m/s  kWh   (P(v, g) - S(c)) dt / 3600 + 0.25 g^2 km   vertical climb_kwh + 0.02
                  dt = km x 1000 / ground speed, g = gust index, c = cloud cover. Wind, gust and cloud = mean of
                  the two node centres.
                  Energy model (spec), in route.odin, also for the ship and the metrics: BATTERY_KWH 180,
                  BATTERY_START 0.86 (a ship leaves with 154.8 kWh), power_kw(v, g) = 3 + 0.0085 v^3 + 6 g,
                  solar_kw(c) = 9 x 0.75 x (1 - 0.78 c) (6.75 kW clear, 1.49 kW overcast), climb_kwh(m) =
                  0.12 kWh per 100 m up, 0.04 per 100 m down (a 250 m layer change: 0.30 / 0.10 kWh).
                  P(11, 0) = 14.3 kW is above the strongest sun, so greenest edges never cost less than zero.
                  Calm and clear at 11 m/s: 0.19 kWh per km, overcast 0.32.
                  Ground speed (spec), ground_speed(v, wind, dir): tailwind + sqrt(v^2 - crosswind^2) along the
                  edge. Blocked when the crosswind is stronger than v (no retry, as the spec reads). Under
                  2.5 m/s the edge is flown at v + 6 m/s (that v also goes into P for greenest), still under
                  1.5 m/s it is blocked. NaN wind blocks the edge.
                  Wind cache: grid.wind / grid.gust hold wind_at / gust_at at every node centre for one hour
                  (12 B x 203k = 2.4 MB in World), grid.cloud cloud_at at every cell centre (one layer, 4 B x 68k
                  = 271 KB), rebuilt when the hour or that hour's forecast changes (compared to a 2.5 KB copy,
                  so a new snapshot is picked up without a flag). Zero is a calm, clear hour 0. The three modes
                  and every route in the same hour share it. Build ~2.6 ms -o:speed (406k bilinear samples).
                  Estimate (grid_estimate) = octile km x lowest cost per km + layer changes x cheapest climb.
                  Lowest cost per km = the mode's cost at airspeed + the strongest wind of the hour (as a pure
                  tailwind), its calmest gust and (greenest) its clearest sky; bilinear sampling never leaves the range of the grid points,
                  so it never overestimates with any snapshot. When the wind can push the ground speed under
                  2.5 m/s (wind_max > v - 2.5) it also takes the cost at v + 6 with ground speed at most
                  min(v + 6 + wind_max, 2.5 + sqrt((v + 6)^2 - v^2)), whichever is lower. Consistent, so an expanded node is never reopened.
                  Weighted x 1.001 to break the many near-ties of an open grid (at most 0.1 % above the cheapest).
                  Checked: cost equals a plain Dijkstra (estimate 0) within 1e-6 on 126 routes x 3 modes, windy
                  and random wind snapshots. Again with ground speed: same found / not found and cost within
                  3.2e-6 relative (f32 sums in another order) on 4455 routes: all hub pairs x 3 modes x hours
                  0 / 4 / 8 on windy.snap and headwind.snap (1607 found), 405 on random wind up to 35 m/s.
                  Again with the energy model: 540 routes (180 random hub pairs x 3 modes, calm and clear plus
                  5 snapshots with random wind up to 36 m/s, gust and cloud 0..1): all found by both, A* at
                  most 0.0003 % above Dijkstra.
                  Path cleanup (spec, in this order, in route() once A* reaches the goal):
                    1. string pulling: from each kept node jump to the farthest of the next 14 nodes (PULL_WINDOW)
                       in the same layer whose straight line is free and costs at most 0.4 % (PULL_TOLERANCE)
                       more than the A* path between them (g.cost difference). line_cost(g, a, b, mode) walks
                       the cells the line crosses (Amanatides-Woo), each piece costs as an edge (flight_cost,
                       shared with edge_cost) with the weather of its cell; a blocked cell or a blocked piece
                       makes the line not free. A line through a cell corner does not enter the cells beside
                       it, the same as a diagonal A* step. Never across a layer change.
                    2. towers: first and last point at the tower top + 6 m (TOWER_ABOVE_M), with a ramp point
                       halfway between the tower and the first (last) node, at that node's altitude (nasr, #45).
                    3. Chaikin x3 (points at 1/4 and 3/4 of every segment, the towers stay), then resampled every
                       RESAMPLE_KM of horizontal distance, the last point is the end tower. 250 m, not the spec's
                       20 m (a 5 km map): the heightmap spacing, so the clearance sees every height cell (nasr, #46).
                       20 m gave ~10.7k points per route and test files over the 1 MB limit.
                    4. slope limit 0.24 (SLOPE_MAX): a forward pass caps the climb, a backward pass the descent,
                       both only lower points and leave the towers, then z >= height_at + 40 m
                       (TERRAIN_CLEARANCE_M).
                  Oostende -> Liege (213 km): 189 A* nodes -> ~15 kept -> 856 points, route arena 2 -> 14 KB.
                  Chaikin cuts corners of the pulled lines, so the smooth path can clip blocked cells: on
                  2700 routes with random zones 3 points were inside a zone, at most 36 m deep (a zone blocks
                  every cell it overlaps, so the cell margin absorbs most of it). Tower legs (hub -> first node,
                  up to 5 cells) are not checked against blocked cells, as in the spec: a hub inside a zone
                  (Mechelen in no_fly.txt) is still reached by its tower leg.
                  Checked (2700 routes: all modes, calm / windy / headwind / cloudy, random zones): ends on the
                  tower tops + 6, chord between points <= 250 m, every slope <= 0.24, every point >= ground + 40.
                  line_cost against a 0.1 m step integration on 19k random lines: cost within 2.1e-6, the free
                  test agreed except one line through a cell corner (the brute force counts the corner).
                  Measured (cloud box, -o:speed): cleanup adds ~0.05 ms to Oostende -> Liege (calm route 0.038 ->
                  0.088 ms), with the height_at stub; estimate ~0.05 ms (~250 lines of ~8 cells x ~20 ns + 856
                  points). Bench route avg 8.6 -> 8.0 ms, three modes 23.0 -> 22.0 ms (noise, A* dominates).
                  Open set: binary min-heap on f in grid.heap (fixed array, 8 B x 203k) with grid.slot
                  (index in the heap, HEAP_CLOSED once expanded) for decrease-key. No allocation during
                  the search, the path is the only allocation (route arena). Search state 28 B x 203k = 5.7 MB.
                  Scan order (for the A* scan animation): grid.expanded[:grid.expanded_len] holds the nodes in
                  the order the last route expanded (popped) them, start first, goal last on success. Fixed
                  array of 203k Node (813 KB) in World: a node is never reopened, so it always fits. Reset to
                  0 at the start of every route, so a route that fails before A* (no free end node, separate
                  regions) leaves an empty scan, and one that fails during A* holds every node it searched.
                  Valid until the next route call. The renderer only reads it, the router does no extra work
                  beyond one store per expanded node. The state dump prints expanded_len.
                  Blocked nodes (spec): highest ground in the cell + 75 m above the layer, the outer ring of
                  cells, or a no-fly zone below its ceiling. w.no_fly: [8]No_Fly_Zone (centre km, radius km,
                  ceiling m), radius 0 = unused slot, zero = no zones. A zone blocks every cell it overlaps,
                  not only the cells whose centre it covers. grid_blocked(g, n) reads one bit.
                  Two bitsets of 25 KB in w.grid: terrain (edge + ground, 25 height_at samples per cell every
                  250 m = the heightmap spacing, 1.7M calls) and blocked = terrain + zones. route() builds terrain
                  on first use and after a hot reload, and rebuilds blocked when w.no_fly differs from the zones
                  it was built with. Nothing in it depends on the forecast hour, so changing hour costs nothing.
                  A* skips blocked neighbours. With blocked also the free regions are labelled (flood fill over
                  the A* steps, grid.region per node, the open heap is the stack): start and goal in different
                  regions fail at once. Without it a walled-in hub expanded every reachable node (33 ms -o:speed).
                  Measured (cloud box, -o:speed / debug): terrain + regions on first use 4 / 120 ms with the
                  height_at stub, zones + regions after a zone change 4 / 42 ms, cached route unchanged
                  (bench three modes avg 22 -> 26 us, mostly the two 11 x 11 free node searches).
                  Checked against a brute force over all 203k nodes (zones overlapping, at the grid edge,
                  partly outside, smaller than a cell, NaN / Inf zones ignored), a whole-grid closest free node,
                  and 135 routes with random zones against a Dijkstra on the blocked grid (same cost within 0.1 %).
                  Measured before the wind costs (cloud box, -o:speed): 2025 routes between all city pairs
                  x 3 x 3 layers, avg 14 us, worst 0.19 ms; corner to corner expands 286 nodes.
                  With wind costs (bench, random wind up to 21 m/s, 4-core cloud box, profile): route avg 6.2 ms
                  incl. the cache build when the hour changes (max 23 ms), three modes avg 14.8 ms (max 89 ms).
                  The estimate assumes the strongest wind as tailwind everywhere, so strong wind means a weak
                  estimate: ~19k expanded nodes per route, ~320 ns each. Without the cache: three modes 33 ms.
                  With ground speed (same box, 3 runs each, A = before / B = after): route avg 5.7-6.2 /
                  6.3-6.8 ms, three modes 14.2-14.9 / 17.0-18.6 ms. The crosswind makes edges dearer than the
                  pure tailwind estimate, so 7-9 % more nodes are visited (fastest 15.3k -> 16.4k, calmest
                  33.7k -> 36.1k, greenest 25.8k -> 28.1k on random wind up to 21 m/s), plus a sqrt per edge.
                  With the energy model (4-core cloud box, profile, 2 runs each, before / after): route avg
                  7.7-8.0 / 8.0-8.2 ms, three modes 20.7-21.5 / 22.2-22.5 ms, within the noise of this box.
                  The cloud cache adds 68k cloud_at calls (~0.7 ms) when the hour changes.
Units everywhere: horizontal km (map space, y down), altitude m, speed m/s, energy kWh.

World memory
  World is bootstrapped inside its own perm arena (virtual memory), so it survives reloads.
  Arenas: perm (World, map, long lived), route_mem (reset per route), frame (temp_allocator, reset per frame).
  w.weather is a fixed-size Weather inside World (22.7 KB), so it needs no weather arena.
  game_update sets context.allocator = perm and context.temp_allocator = frame.

BUILD
compile.sh [debug|profile|release] [extra odin flags], build.sh wraps it with build-notify
  Linux and macOS. macOS has bash 3.2 and BSD tools: raylib is copied only when newer with [ -nt ]
  (no cp -u), the build time comes from perl Time::HiRes (no date %N), no mold, game.dylib + libraylib.620.dylib,
  rpath @loader_path (the dylib's install name is @rpath/libraylib.620.dylib).
compile.bat same modes on Windows (no mold, raylib.dll copied to build\, random pdb name per build
  so a loaded pdb never blocks the next build, host not rebuilt while drift.exe runs,
  release uses -subsystem:windows). format.bat / check.bat run the .sh versions with Git for Windows sh.
  all modes: -vet -vet-cast -strict-style -warnings-as-errors, -linker:mold on Linux, prints build time
  debug:   host + game.so, -debug -o:none -use-separate-modules (~900 ms for both, 2026-11-21 after
           profiler / headless / log / dump: 874-917 ms, main before them 767-875 ms; limit 2 s)
           game.so uses raylib as a shared lib (RAYLIB_SHARED), copied to build/, rpath $ORIGIN,
           so raylib state survives reloads. Outputs are written to a temp name, then moved.
  profile: source/release, -debug -o:speed, single exe (~2 s)
  release: source/release, -o:speed -disable-assert, single exe (~1.7 s)
  ASAN=1 adds -sanitize:address
  build flags in code: DRIFT_DEBUG / DRIFT_PROFILE (#config in game.odin), set with -define by compile.sh / .bat
           (debug game.so: DRIFT_DEBUG, profile: DRIFT_PROFILE, release: neither). Odin rejects a -define
           nobody reads, so the host gets none. BUILD_MODE is printed at startup ("[game] build: debug").
