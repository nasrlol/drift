MAP DATA

Source: OpenStreetMap extract of Belgium from Geofabrik (ODbL, credit "(c) OpenStreetMap contributors")
  https://download.geofabrik.de/europe/belgium/belgium-261119.osm.pbf
  saved as assets/raw/belgium.osm.pbf (668 MB, not in git)
  note: the "belgium-latest" link was broken (404), so we use a dated file

Tool: GDAL (ogr2ogr), installed with micromamba, no sudo:
  micromamba create -n gis -c conda-forge gdal

tools/extract_map.sh
  pulls 4 layers out of the .pbf into assets/geojson/ (1.7 MB total)
    border.geojson     Belgium outline (1 polygon)
    rivers.geojson     waterway=river
    motorways.geojson  highway=motorway
    cities.geojson     place=city (15 points)
  keeps only the name field, simplifies lines, 5 decimal coordinates
  takes a few minutes (most of it on the border)

tools/bake_map/  (odin run tools/bake_map, from repo root)
  reads the geojson files, writes assets/belgium.bin (422 KB)
  projection: equirectangular, km, origin top-left (lon 2.38, lat 51.56), y down
  10872 lines, 36364 points, 15 cities, 15 hubs

belgium.bin format (version 2, all little endian, 4-byte aligned)
  header  magic "DRFT", version, line_count, point_count, city_count, hub_count (6 x u32)
  lines   start, count, kind (3 x u32)   kind: 0 border, 1 river, 2 motorway
  points  x, y (2 x f32, km)
  cities  pos (2 x f32), name (32 bytes, 0-terminated)
  hubs    pos (2 x f32), name (32 bytes, 0-terminated). For now one hub per city, same position.
          max MAX_HUBS = 32 (bake fails above that). Tower top = ground + HUB_TOWER_M (58 m, spec).

WEATHER DATA

Source: Open-Meteo forecast API v1 (CC BY 4.0, free for non-commercial use, no key)
  https://api.open-meteo.com/v1/forecast
  one request for all 63 grid points: latitude=..&longitude=.. (comma lists),
  hourly=wind_speed_{975,950,925}hPa,wind_direction_{975,950,925}hPa,wind_speed_10m,wind_gusts_10m,cloud_cover,
  forecast_hours=9&wind_speed_unit=ms&timezone=GMT&timeformat=unixtime
  hour 0 = the current UTC hour. Open-Meteo counts every location as one call (10000 / day free),
  so 63 points refreshed every 15 min = ~6000 / day. A finer grid needs a slower refresh.
Grid: 9 x 7 points every 40 km from the map origin (lon 2.38, lat 51.56), covers the 285 x 229 km map.
  lat = 51.56 - y / 111.32, lon = 2.38 + x / (111.32 cos 50.5), same projection as the bake tool.
Gust index: Open-Meteo has gusts only at 10 m. index = clamp((gust_10m - wind_10m) / 10 m/s, 0, 1)
  x (1.08 - LAYER_ALT / 1600), the height factor from the spec. Cloud = cloud_cover % / 100 (total cover).
Validation (reject the whole response, keep the old snapshot): 63 locations, 9 values per series, no null,
  wind speeds and gusts 0..100 m/s, directions 0..360, cloud 0..100 %, times 2020..2100 on whole hours,
  hour h = start + h x 3600 in every cell. The range test also rejects NaN and +-Inf.
  Checked by feeding edited responses (null, out of range, shifted time, short series, 62 locations, Inf, html).
Measured (2026-11-21, macOS arm64): one fetch ~400 ms, ~1.2 MB scratch (json values).

CODE LAYOUT
source/game/      package game, all game code, builds as build/game.so (debug) or into the exe (release)
  game.odin       World struct, exported procs, fixed 60 Hz timestep, drawing
                  Sim speed: keys 1..4 set w.sim_speed = 1x / 5x / 15x / 40x (SIM_SPEEDS). The frame time (capped at
                  0.25 s) is multiplied before it goes into the accumulator, so 40x runs up to 40 steps per 60 fps frame
                  (600 at most after a hitch) and every step still has dt = 1 / 60.
                  Camera: w.view (View) = pan (km from the map centre to the screen centre) + zoom (log2 relative
                  to the fitted view, ZOOM_MIN -1 .. ZOOM_MAX 7). Zero = the whole map fitted to 95% of the window.
                  Each frame it becomes a Camera2D, zoom = px per km. Pan is clamped so the screen centre stays on
                  the map. Two modes, key M toggles, w.drive_mode (zero = map mode):
                  Map mode: the camera reads w.controls, throttle / turn pan (600 px/s), climb zooms (2 per s) around
                  the screen centre. So WASD and the left stick pan, R/F and right stick Y zoom. Mouse (camera only,
                  not in Controls): left drag pans, wheel zooms (0.25 per notch) around the cursor. The ship does not
                  step and nothing is recorded.
                  Drive mode: Controls go to ship_step and the replay record, the camera sits on the ship, only the
                  wheel zooms. The ship is drawn as an 8 px red triangle pointing along its heading in both modes.
                  Colors (render.odin): every drawn color comes from Palette, PALETTES has one per Theme (Day,
                  Night). w.theme (zero = Day) picks it, key T toggles. World keeps the enum, not a pointer: a pointer
                  into this library's constants would dangle after a hot reload. The map line colors go to the mesh
                  shader as a uniform, so switching the theme does not rebuild anything. The profiler overlay keeps
                  its own fixed colors.
                  Map drawing (render.odin, built inline in game_update): the whole map is one static mesh, built on
                  the first frame (needs the window, never in headless) and drawn with one rl.DrawMesh in Mode2D.
                  Each segment is a quad of 6 vertices (2 triangles, no index buffer: raylib indices are u16 and
                  153k vertices do not fit). vertexNormal = other end of the segment + the side to push to,
                  vertexColor.r = Map_Kind. The vertex shader (MAP_VS, GLSL 330) widens each quad to 1 px along the
                  screen space normal, so lines stay 1 px at every zoom; colors are a uniform per kind.
                  25493 segments, 152958 vertices, 4.1 MB on the GPU, built in the frame arena and freed after the
                  upload (mesh pointers set to nil so UnloadMesh only frees GPU buffers). Rebuilt after a hot reload
                  (the shaders may have changed), unloaded in game_shutdown.
                  Measured 2026-11-21 (Asahi M2, 800 x 450, debug): draw 8.6 ms with DrawLineStrip -> 0.55 ms with
                  the mesh (the rest is city text and the overlay). The first frame takes ~34 ms (mesh build).
                  Cities: after EndMode2D, each w.m.cities pos goes through GetWorldToScreen2D, black 3 px dot +
                  name (default font, 10 px) right of it, so both keep their pixel size at every zoom. No overlap
                  culling yet (labels todo). The default font covers Latin-1, "Liege" with e grave draws correctly.
  map.odin        same structs as the bake tool (keep in sync). #load embeds belgium.bin,
                  load_map() slices it, no parsing. Re-pointed in game_hot_reloaded.
                  Hubs are copied into a fixed array w.m.hubs[:w.m.hub_count], hub id = index.
  terrain.odin    height_at(w, x, y) -> ground height in m. Stub: 0
  weather.odin    wind_at(w, x, y, layer, hour) -> [2]f32 m/s, direction the wind blows toward, x east, y south
                  gust_at(w, x, y, layer, hour) -> 0..1, cloud_at(w, x, y, hour) -> 0..1. Bilinear on the 40 km grid
                  from w.weather, no allocation. Outside the grid the edge value holds, layer and hour are
                  clamped (hours after 8 keep hour 8). Until a snapshot is loaded w.weather is zero: calm, clear.
                  3 layers = 975 / 950 / 925 hPa ~ LAYER_ALT 300 / 550 / 800 m, hours 0..8 from snapshot start
                  Weather struct: start (unix s), wind [hour][layer][cell][2]f32, gust [hour][layer][cell] 0..1,
                  cloud [hour][cell] 0..1. Fixed size 22.7 KB, zero = calm and clear.
  net.odin        fetch_weather(out, scratch, cancel) -> ok: blocking Open-Meteo request with curl (15 s timeout,
                  max 1 MB, aborts within ~1 s when cancel is set), converts the json into a Weather.
                  Writes out only if every value is valid.
                  Snapshot cycle (state in w.fetch, zero = fetch on the first update):
                    game_init -> weather_load_snapshot(w, path): reads cache/weather.snap, checks size, magic, version,
                      sha256 and weather_valid. Bad or missing file: weather stays zero, fetch right away.
                    game_update -> weather_poll: every frame, starts a thread when now >= next (15 min after
                      the snapshot was fetched, 5 min after a failure). The thread fetches, hashes and writes
                      the file (temp + rename), all allocation in w.fetch.mem. When is_done, the frame loop
                      copies the 22.7 KB Weather into w.weather. No network or disk IO in the frame loop.
                    game_before_reload / game_shutdown -> weather_stop: cancel + join (measured 5-14 ms),
                      because the thread runs code from the library that is about to be unloaded.
                  cache/weather.snap: Snapshot_Header (magic "DRWS", version 1, fetched_at unix s,
                  sha256 of the Weather bytes) + raw Weather, 22736 bytes. w.weather_hash = that sha256.
                  Identity: game_init -> identity_load_or_create. cache/identity.key holds the 32 byte ed25519
                    seed (owner-only permissions). Missing: generate from the system entropy source and save.
                    Present but wrong size or invalid: logged and left alone (it is the user's reputation),
                    w.identity stays zero and network features stay off. w.identity_pub = public key,
                    logged as the first 8 bytes in hex. Moves to the user data folder with the release item.
                  Carpool messages: Message is 184 bytes, fixed size, little endian, no implicit padding
                    (#assert). Header: magic "DRMS", version 1, kind (Offer / Request / Accept / Review),
                    time (unix s, set by the author), author (ed25519 public key). Body is a raw union:
                      Offer   from_hub, to_hub, seats 1..8, mode, depart, arrive, weather snapshot hash, energy_kwh
                      Request offer id, from_hub, to_hub, seats 1..8
                      Accept  offer id, request id
                      Review  subject public key, accept id, stars 1..5
                    sig = ed25519 over bytes 0..119. Message id = sha256 of all 184 bytes.
                    msg_sign(w, m) fills magic, version, author, sig (start from a zeroed Message).
                    msg_read(w, bytes) for anything from outside: size, header, field ranges, then signature.
                    Measured (macOS arm64, -o:speed): sign ~33 us, read + verify ~44 us.
                  The same format is used by headless --snapshot, test/data and bench. Logs go to stderr.
  debug.odin      tools for finding bugs. Profiler: prof_begin() / prof_end(w, block, tick) store the last ms of
                  Update, Draw, Route, Weather_Load in w.prof, compiled out in release (PROFILING =
                  DRIFT_DEBUG || DRIFT_PROFILE). Overlay drawn in game_update, F3 toggles: frame ms with
                  update / draw split, worst of the last 120 frames, route and weather load ms, perm / route
                  arena used / reserved, frame arena use, 120 frame graph (yellow line = 4 ms budget, red bars
                  over it). Frame ms excludes EndDrawing (vsync wait) and the overlay itself.
                  Headless: ./build/drift --headless --snapshot <file> --inputs <file> runs without a window,
                  prints the result to stdout (deterministic text, no timings) and timings / errors to stderr,
                  exit code 0 or 1. game_headless (exported, called by host and release main) reads the inputs,
                  headless_run(w, snapshot_path, inputs, out) loads the snapshot (weather_load_snapshot, the
                  cache/weather.snap format) and does the work and is what test/ calls.
                  Inputs: one command per line, # comment. "route <from hub> <to hub> <mode> <hour>",
                  hub = index into w.m.hubs, mode fastest / greenest / calmest, hour 0..8.
                  "no_fly <x km> <y km> <radius km> <ceiling m>" fills the next free slot of w.no_fly.
                  Output per route: "route 6 -> 11 fastest hour 0: 2 points, 104.812 km", then x y alt per point.
                  --dump appends the state dump after the result.
                  Log: logf(w, system, format, args) prints "[route t=1234] message" to stderr, t = w.tick.
                  No allocation (1 KB stack buffer, longer messages are cut). Code without a World
                  (fetch thread, argument parsing) prints "[system] message" with fmt.eprint.
                  State dump: dump_world(w, out) writes tick, build, map counts, hubs, weather start / sha256 /
                  fetched_at, a weather line per hour
                  (max wind per layer, max gust, mean cloud), no-fly zones, blocked nodes per layer
                  and arena used / reserved. No timings, so two dumps
                  of the same run are identical. F5 in the app prints it to stdout, --dump in headless mode.
                  Windows release is -subsystem:windows and has no console: use the debug or profile exe there.
  ship.odin       Controls struct: throttle, turn, climb, each -1..1, zero = neutral. Filled by input, read by the
                  camera in map mode (game.odin), by ship_step in drive mode.
                  Ship: pos (km, map space), alt (m), heading (rad clockwise from north), speed (m/s), turn_rate (rad/s).
                  ship_step(w, controls, dt) runs once per fixed 60 Hz step in game_update on w.ship, reads only the
                  ship, the controls and height_at. Limits: speed follows max(throttle, 0) * 35 m/s with +1.2 / -1.6
                  m/s^2, turn rate follows turn * 0.6 rad/s with a 0.5 s time constant, climb 5 m/s, altitude clamped
                  to height_at + 28 m .. 900 m. Wind: ground velocity = heading * speed + wind_at of the layer nearest
                  to the altitude, hour = tick / (60 * 3600). Battery comes later.
                  Ship.warnings: bit_set of Terrain (less than 60 m above the ground) and No_Fly (inside a w.no_fly
                  circle below its ceiling), rebuilt every step. The UI only reads it.
                  Ship.docked / dock_hub: set when within 30 m horizontally and 25 m vertically of a hub's tower top
                  (ground + HUB_TOWER_M), first hub in index order, rebuilt every step.
                  Replay: every step the controls are packed to Control_Step ([3]i8, 3 bytes) and the ship steps with the
                  unpacked value, so the recording reproduces the path exactly. w.replay.steps is 60 * 3600 steps (1 h,
                  648 KB) from the perm arena, w.replay.count says how many are filled, recording stops when full.
                  Bench (profile build, 2026-11-21, Windows, height_at still a stub): ship_step min 59 / avg 65 / max 319 ns
                  against the 1 us budget. It is ~2 sin/cos, wind_at (8 ns), 15 hub distances and 8 zone checks. The tower
                  height_at is only called for a hub that is within 30 m horizontally, not for all 15, because the real
                  height_at will cost more than the stub.
  input.odin      read_controls() -> Controls, called once per frame into w.controls. W/S throttle, A/D turn (right = +),
                  R/F climb up / down, gamepad 0: left stick throttle + turn, right stick Y climb. Keyboard and stick
                  add up, clamped to -1..1. Deadzone 0.15, rescaled so the stick still reaches 1.
  route.odin      route(w, from, to, mode, hour) -> (path, ok). Points are [3]f32 (x km, y km, alt m).
                  ok = false means no safe route with this wind. Hub positions: w.m.hubs.
                  Path lives in w.route_mem until the next call: from, the centres of the grid nodes
                  in between, to. A* never enters a blocked node (see below).
                  ok = false also when from or to has no free node within 5 cells (outside the grid,
                  inside a no-fly zone): grid_free_node_near picks the closest free cell centre, lowest free
                  layer first (spec), the altitude of the end point is not used.
                  Grid: 286 x 237 cells of 1 km x 3 layers (LAYER_ALT) = 203,346 nodes, covers every point
                  in belgium.bin (x 0.6..285.2, y 1.0..236.5 km). node = layer * 286 * 237 + y * 286 + x,
                  each layer a contiguous row-major plane. grid_node_at(pos) snaps to the cell under x, y
                  and the closest layer, grid_node_pos(n) gives the cell centre, grid_neighbor(n, d) steps
                  one entry of GRID_DIRS (8 horizontal directions, up, down) and fails past the edge.
                  w.grid holds the search state as fixed arrays in World (no arena, allocated with World):
                  visit stamp, cost, parent, heap slot and heap item per node. A node's cost and parent only
                  count when visit[n] == grid.search, so a route starts with search += 1, not a 4.9 MB clear.
                  A*: cost = km flown (1 or sqrt 2 per cell, layer change = altitude difference / 1000).
                  mode and hour are not used yet (cost per mode and wind are the next todo items).
                  Estimate (grid_estimate) = octile distance + altitude difference: exact on an empty grid,
                  never too high, consistent, so an expanded node is never reopened. Weighted x 1.001 to
                  break the many near-ties of an open grid (paths at most 0.1 % longer than the cheapest).
                  Open set: binary min-heap on f in grid.heap (fixed array, 8 B x 203k) with grid.slot
                  (index in the heap, HEAP_CLOSED once expanded) for decrease-key. No allocation during
                  the search, the path is the only allocation (route arena). Search state 24 B x 203k = 4.9 MB.
                  Measured (cloud box, -o:speed): 2025 routes between all city pairs x 3 x 3 layers,
                  avg 14 us, worst 0.19 ms; corner to corner expands 286 nodes (35k without the weight).
                  Debug build: avg 0.14 ms, worst 0.6 ms. With test walls the cost matched a plain Dijkstra.
                  Blocked nodes (spec): highest ground in the cell + 75 m above the layer, the outer ring of
                  cells, or a no-fly zone below its ceiling. w.no_fly: [8]No_Fly_Zone (centre km, radius km,
                  ceiling m), radius 0 = unused slot, zero = no zones. A zone blocks every cell it overlaps,
                  not only the cells whose centre it covers. grid_blocked(g, n) reads one bit.
                  Two bitsets of 25 KB in w.grid: terrain (edge + ground, 25 height_at samples per cell every
                  250 m = the heightmap spacing, 1.7M calls) and blocked = terrain + zones. route() builds terrain
                  on first use and after a hot reload, and rebuilds blocked when w.no_fly differs from the zones
                  it was built with. Nothing in it depends on the forecast hour, so changing hour costs nothing.
                  A* skips blocked neighbours. With blocked also the free regions are labelled (flood fill over
                  the A* steps, grid.region per node, the open heap is the stack): start and goal in different
                  regions fail at once. Without it a walled-in hub expanded every reachable node (33 ms -o:speed).
                  Measured (cloud box, -o:speed / debug): terrain + regions on first use 4 / 120 ms with the
                  height_at stub, zones + regions after a zone change 4 / 42 ms, cached route unchanged
                  (bench three modes avg 22 -> 26 us, mostly the two 11 x 11 free node searches).
                  Checked against a brute force over all 203k nodes (zones overlapping, at the grid edge,
                  partly outside, smaller than a cell, NaN / Inf zones ignored), a whole-grid closest free node,
                  and 135 routes with random zones against a Dijkstra on the blocked grid (same cost within 0.1 %).
Units everywhere: horizontal km (map space, y down), altitude m, speed m/s, energy kWh.

source/host/      debug host: loads build/game.so (game.dll on Windows), checks its mtime every frame, copies it to
                  build/game_N.so and loads the copy, unloads the old one after. Compares memory_size,
                  refuses a reload if World changed (restart needed). Calls game_before_reload on the old
                  library right before unloading it (stops the weather thread). Run from the repo root.
source/release/   release main: calls the game package directly, one static exe

World memory
  World is bootstrapped inside its own perm arena (virtual memory), so it survives reloads.
  Arenas: perm (World, map, long lived), route_mem (reset per route), frame (temp_allocator, reset per frame).
  w.weather is a fixed-size Weather inside World (22.7 KB), so it needs no weather arena.
  game_update sets context.allocator = perm and context.temp_allocator = frame.

BUILD
compile.sh [debug|profile|release] [extra odin flags], build.sh wraps it with build-notify
  Linux and macOS. macOS has bash 3.2 and BSD tools: raylib is copied only when newer with [ -nt ]
  (no cp -u), the build time comes from perl Time::HiRes (no date %N), no mold, game.dylib + libraylib.620.dylib,
  rpath @loader_path (the dylib's install name is @rpath/libraylib.620.dylib).
compile.bat same modes on Windows (no mold, raylib.dll copied to build\, random pdb name per build
  so a loaded pdb never blocks the next build, host not rebuilt while drift.exe runs,
  release uses -subsystem:windows). format.bat / check.bat run the .sh versions with Git for Windows sh.
  all modes: -vet -vet-cast -strict-style -warnings-as-errors, -linker:mold on Linux, prints build time
  debug:   host + game.so, -debug -o:none -use-separate-modules (~900 ms for both, 2026-11-21 after
           profiler / headless / log / dump: 874-917 ms, main before them 767-875 ms; limit 2 s)
           game.so uses raylib as a shared lib (RAYLIB_SHARED), copied to build/, rpath $ORIGIN,
           so raylib state survives reloads. Outputs are written to a temp name, then moved.
  profile: source/release, -debug -o:speed, single exe (~2 s)
  release: source/release, -o:speed -disable-assert, single exe (~1.7 s)
  ASAN=1 adds -sanitize:address
  build flags in code: DRIFT_DEBUG / DRIFT_PROFILE (#config in game.odin), set with -define by compile.sh / .bat
           (debug game.so: DRIFT_DEBUG, profile: DRIFT_PROFILE, release: neither). Odin rejects a -define
           nobody reads, so the host gets none. BUILD_MODE is printed at startup ("[game] build: debug").
release exe links raylib statically, map is embedded, only depends on libc, libm and X11
